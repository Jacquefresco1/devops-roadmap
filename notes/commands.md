## Навигация
pwd - показывает текущее местоположение(папка в которой находишься).

## Git

git status - показывает информацию после изменений файлов.

git add "название файла" - добавляет изменение или новый файл в standing.

git add . - добавляет всю текущую директорию со всеми файлами и другими поддиркториями в ней в standing.

git commit -m "Название того что сделал" - все что добавил в add сохраняется в историю git(commit).

git branch -d "название ветки" - удаляет локальную ветку, не удалит если есть незамерженные изменения.

git branch -D "название ветки" - удаляет без вопросов.

git log --oneline - показывает историю commit, а именно то что было в скобочках.

git diff - показывает изменения в файлах, которые еще не добавлены в standing(git add)..

git diff --staged - показывает тоже самое что и просто git diff, но после команды git add(когда файл добавлен в standing).

git diff --cached - тоже самое, можно использовать или то или то.

git diff <branch1> <branch2>
→ показывает различия между двумя ветками/состояниями

git diff <banch1> <origin/branch> - показывает различие межу локлаьной веткой и удаленной.

git restore "название файла без скобочек" - отменяет изменение в файле, до того момента который был добавлен последним в standing.

git restore --staged "название файла" - убирает изменение которое было добавлено в git add(standing), но не убирает само изменение с файла.

git restore --source "название ветки" -- . - восстанавливает в данной ветке содержимое с указаной ветки(переносит).

git reset --soft HEAD~1 - убирает изменение в текущем commit, но оставляет изменения в standig и в самом файле ~1(указывает на сколько коммитов мы возвращае>

git reset --mixed HEAD~1 - убирает изменение в текущем commit так же убирает изменения с standing, оставляя их только в самом файле.

git reset --hard HEAD~1 - сносит все изменения до предыдущего commit.

git branch - показывает локальные ветки. * - значек возле ветки в которой находишься.

git branch "название без скобочек" - создает ветку с указаным названием, но не переключает на нее.

git branch -m "название без скобочек" - переименовывает ветку в которой находишься.

git branch -vv
Показывает все локальные ветки, их upstream и последний commit.

git branch -u origin/<branch>
Устанавливает или изменяет upstream текущей локальной ветки.
Например:
git branch -u origin/Linux
После этого текущая ветка отслеживает origin/Linux.

git branch --unset-upstream
Удаляет upstream у текущей локальной ветки.

git push -u origin <branch>
Отправляет указанную локальную ветку в origin и одновременно устанавливает для неё upstream.
Например:
git push -u origin Linux
Создаёт/обновляет origin/Linux и связывает:
Linux → origin/Linux

git push origin HEAD:<branch>
Отправляет текущую ветку (HEAD) в указанную удалённую ветку.
Например:
git push origin HEAD:Linux
Если текущая ветка называется upstream-test, её изменения будут отправлены в origin/Linux.

git fetch
Получает актуальную информацию с remote и обновляет локальные remote-tracking ветки (origin/main, origin/Linux и т.д.).
Текущую локальную ветку не изменяет.
После fetch можно сравнить свою ветку с актуальным состоянием remote.

git fetch origin <branch>
→ получает информацию о конкретной удалённой ветке

git merge <branch>
Интегрирует указанную локальную ветку в текущую.
Например:
git switch Linux
git merge merge-test
Изменения и история merge-test добавляются в Linux.
Сама merge-test при этом не изменяется.
Если истории разошлись, Git может создать merge commit.
Если изменения конфликтуют, Git остановит merge и попросит разрешить конфликт вручную.

git merge "remote"/"ветка" - git merge origin/Linux вливает удаленную ветку в текущую.

git switch "название" - переключает на указаную ветку

git switch -c "название" - создает новут ветку и сразу переключает на нее.

git push origin --delete "название ветки" - удаляет ветку с github.

git rm "название файла без скобочек" - удаляет файл и сообщает об это git. Как git add, только наоборот.

git rm -r "название папки" - удаляет папку и все содержимое, если вместо названия указать "." удалит текущую папку и ее содержимое.

git remote -v - показывает удаленные репозитории. Origin - обычно имя github-репозитория.

git push - отправляет локальные коммиты на github.

git push --force-with-lease - безопаснее принудительного push; переписывает remote-историю только если remote не изменился неожиданно.

git log --oneline --graph --all --decorate - показывает общую историю коммитов всех веток.(oneline - один комит в одну строку; graph - визуальные линии ветвления; all - истории всех веток, не только текущей; decorate - показывает HEAD, название веток и другие указатели).

git reflog - история перемещений HEAD,то есть показывает доп инфу, если сравнить с log.

git clone "ссылка с гитхаб на url" - создает клон репозитории в отдельную папку или же, если ты вытягиваешь с нуля, то получаешь все зодержимое для работы.

git diff "ветка1" "ветка2" - показывает различие между двумя ветками(между клоном и оригиналом) или между двумя любыми.

git pull - добавляет изменения с гит хаб в клон(текущую ветку).

git pull "remote" "ветка1" - (git pull origin Linux) бучили в клоне, ты можешь вытянуть данные с конкретной удаленной ветки, не обязательно с той которую скопировал изначально.

git log "ветка1" "ветка2" - показывает коммиты, которые которые есть в одной ветке, но отсутвуют в другой.

git rebase "ветка или удаленная ветка" - выравнивает историю(переносит текущую историю коммит поверх указаной ветки).

git rebase --continue — продолжить rebase после разрешения конфликта.

git rebase --abort — отменить незавершённый rebase и вернуть состояние до его начала.

git restore --source C --staged --worktree config.txt — берёт config.txt из commit C; восстанавливает его в working tree; одновременно обновляет staging.

git restore --source C config.txt — Если нужен только working tree

git log origin/feature..feature --oneline — Показывает commit’ы, которые есть в feature, но отсутствуют в origin/feature.
Можно сделать наоборот. 

git log -1 --oneline — Быстрый способ посмотреть последний коммит.

git push --force-with-lease — Используется, когда история уже была опубликована, а затем переписана, например через rebase.

git push --force — но он грубее. Для нормальной практики запоминаем прежде всего --force-with-lease.

git rebase --skip — пропустить текущий commit, который Git пытается перенести.

## BASH
## Variables

name="Alex" - Создание переменной.

$name - Подстановка значения переменной.

"$name" - Подстановка значения с сохранением его как одного аргумента.

'$name' -  Переменная не подставляется — $name воспринимается буквально как текст.

## Command substitution

$(command) - Выполняет команду и подставляет её результат.

Пример:

today=$(date) - выполняет date и сохраняет результат в today.

echo "Today: $(date)" - выполняет date непосредственно внутри команды echo.

## Exit status

$? - Показывает(содержит) exit status непосредственно предыдущей команды.

0 - команда завершилась успешно.

не 0 - команда завершилась с ошибкой/неуспешно.

Важно: Любая команда после выполнения возвращает exit status. Если между интересующей командой и "$?", выполнить другую команду, то "$?" уже относится к ней.

## Сохранение exit status

Если результат команды нужно использовать позже, его нужно сразу сохранить в переменную:

result="$?" - После этого result хранит полученное значение независимо от того, какие команды выполняются дальше.

Например:

ls "$1"

result="$?"

echo "Something"

if [ "$result" -eq 0 ]; then

	...

fi

echo изменит $?, но result останется прежним.

Почему нужно сохранять $?: $? всегда относится только к непосредственно предыдущей команде.

Пример:

ls "$1"

echo "Hello"

После echo: $? → результат echo. Результат ls уже потерян.

Поэтому:

ls "$1"

result="$?"

сохраняет результат ls до выполнения следующей команды.

## Проверка exit status через if

Можно проверить сохранённый результат:

if [ "$result" -eq 0 ]; then

	echo "Success"

else

	echo "Failed"

fi

Для нескольких вариантов:

if [ "$result" -eq 0 ]; then

	...

elif [ "$result" -eq 2 ]; then

	...

else

	...

fi

## Разные exit status

Ненулевой exit status не обязательно означает одно и то же. Например, разные команды могут возвращать разные коды ошибок.

Поэтому можно различать:

0 → успех

2 → конкретная ошибка

другое ненулевое значение → другая/неизвестная ошибка

Важно: конкретный код имеет смысл только в контексте команды, которая его вернула.

exit 0 → явно завершить скрипт успешно.

exit 1 → явно завершить скрипт с ошибкой.

exit N → завершить скрипт с указанным кодом N.

## Переменные и $

При обращении к значению переменной используется $:

result="0"

"$result" → значение переменной result.

result → имя переменной, а не её значение.

Поэтому:

[ "$result" -eq 0 ]

а не:

[ result -eq 0 ]

Кавычки вокруг переменных

Предпочтительный вариант:

"$result"

"$1"

"$2"

В условиях числового сравнения Bash часто справится и без кавычек, если значение гарантированно простое число, но привычка использовать "$variable" делает код безопаснее и последовательнее.

## Exit status в if

Команду можно проверять через её exit status непосредственно в if:

if command; then

	...

else

	...

fi

В этом случае if автоматически использует exit status команды.

Это отличается от:

command: result="$?"

if [ "$result" -eq 0 ]; then

	...

fi

Первый вариант подходит, когда результат нужен только для принятия решения.

Второй вариант подходит, когда exit status нужно сохранить, вывести или использовать несколько раз.

## File tests

-f – Проверяет, существует ли объект и является ли он обычным файлом.

-d – Проверяет, существует ли объект и является ли он директорией.

-e – Проверяет, существует ли объект вообще.

Пример:

[ -f test.txt ]

[ -d backup ]

[ -e test.txt или backup ]

Exit status этих проверок тоже можно использовать в if.

## if / elif / else

if условие; then

    команда

else

    команда

fi 

if проверяет exit status условия/команды: 

0(true) → then

не 0(false) → else

Можно проверять команду напрямую:

if ls /tmp; then

    ...

else

    ...

fi

elif - "иначе, если". Используется для проверки нескольких последовательных условий.

if условие; then 

	команда 

elif условие; then 

	команда 

else 

	команда 

fi

Bash проверяет условия сверху вниз и выполняет первую подходящую ветку.

if с прямой проверкой команды

if команда; then 

	команда 

else 

	команда 

fi

if непосредственно проверяет exit status выполненной команды:

0 → then 

не 0 → else

Пример:

if ls /tmp; then 

	echo "Command succeeded" 

else 

	echo "Command failed" 

fi

## Case

case - Используется, когда одно значение нужно сравнить с несколькими вариантами.

case "$1" in 

	start) 

	echo "Starting" 

	;; 

	stop) 

	echo "Stopping" 

	;; 

	*) 

	echo "Unknown command" 

	;; 

esac

	start|Start) 

	echo "Starting" 

	;;

| — позволяет указать несколько вариантов для одной ветки.

"*" — любой вариант, который не совпал с предыдущими.

;; — завершает текущую ветку case.

esac — завершает конструкцию case.

## AND / OR

[ -d backup ] && [ -f test.txt ]

&& - AND — оба условия должны быть успешными.

&& - следующая команда выполняется, если предыдущая завершилась успешно.

[ -d backup ] || [ -f test.txt ]

|| - OR — достаточно успешного выполнения хотя бы одного условия.

|| - следующая команда выполняется, если предыдущая завершилась неуспешно.

Пример:

[ -d backup ] && echo "Backup exists"

[ -d backup ] || echo "Backup does not exist"

Простая комбинация:

[ -d backup ] && echo "Backup exists" || echo "Backup does not exist"

Важно: A && B || C не всегда эквивалентно if/else. Если B завершится с ошибкой, может выполниться C.

## Exit

exit - немедленно завершает весь скрипт.

exit 0 → завершить с exit status 0. 

exit 1 → завершить с exit status 1. 

exit без числа → завершить с exit status последней выполненной команды.

## Shebang

 #!/bin/bash - Указывает системе использовать Bash для запуска скрипта при запуске:

./script.sh

При:

bash script.sh

Bash уже явно указан командой запуска.

Разница между ;; и exit

exit → завершает весь скрипт.

## Positional parameters

$0 - Имя/путь запускаемого скрипта.

$1

$2

$3

... 

Первый, второй, третий и следующие аргументы, переданные скрипту.

Например:

bash day7.sh Linux Bash DevOps

Дает:

$1 → Linux

$2 → Bash

$3 → DevOps

$# - Количество аргументов, переданных скрипту.

Например:

bash day7.sh Linux Bash DevOps

Дает:

$# = 3

Важно!

Количество не зависит от того, используешь ли ты эти аргументы в коде.

$@ - Все аргументы, переданные скрипту.

$@ - все аргументы 

"$@" - все аргументы с сохранением границ каждого отдельного аргумента.

Например: 

bash day7.sh "Linux Bash" DevOps

Дает: 

два аргумента

$1 → Linux Bash

$2 → DevOps

$# → 2

# Числовые сравнения

-eq — равно

-ne — не равно

Пример:

[ “$#” -eq 2 ]

[ “$#” -ne 2 ]

# Строковые сравнения

= — строки равны

!= — строки не равны

Пример:

[ “$1” = “check” ]

[ “$1” != “check” ]

-eq и -ne используются для числового сравнения.

= и != используются для сравнения строк.

## Argument validation

Типичный порядок проверки аргументов:

1. Проверить количество аргументов.

2. Проверить значение аргумента.

3. Выполнить основную логику.

Пример:

if [ “$#” -ne 2 ]; then

	echo “Usage: day9.sh”

	exit 1

fi

if [ “$1” != “check” ]; then

	echo “Unknown command”

	exit 1

fi

# Early exit

Ранний выход — сначала проверяются условия, необходимые для работы скрипта.

Если условие не выполнено:

	echo “Error”

	exit 1

Если выполнение дошло дальше, значит предыдущие проверки уже пройдены.

# Nested conditions

Конструкции Bash можно вкладывать друг в друга.

if внутри case:

case “$1” in

	check)
		
		if [ -f “$2” ]; then
		
			echo “File exists”
		
		else
		
			echo “File does not exist”
		
		fi

	;;
esac

case внутри if:

if [ “$#” -eq 2 ]; then

	case “$1” in

		check)

		echo “Checking”

		;;

		status)

		echo “Status”

		;;

	esac

fi

if внутри if и case внутри case также допустимы.

if → fi

case → esac

ветка case → ;;

# Проверка нескольких условий

[ “$#” -eq 2 ] && [ “$1” = “check” ]

&& требует успешного выполнения обоих условий.

Работа с аргументами после проверки количества

Если перед началом основной логики уже выполнено:

if [ “$#” -ne 2 ]; then

	exit 1

fi

то дальше скрипт может рассчитывать, что существует:

$1 — первый аргумент

$2 — второй аргумент

Проверять “$#” повторно внутри каждой ветки обычно уже не требуется.

# Практический CLI-паттерн

if [ “$#” -ne 2 ]; then

	echo “Usage: day9.sh ”

	exit 1

fi

case “$1” in

	check)

	…

	;;

	exists)

	…

	;;

	status)

	…

	;;

	*)

	echo “Unknown command”

	exit 1

	;;

esac

## Functions

function_name() {

    commands

}

- Объявление функции. Код внутри не выполняется сразу.

function_name

- Вызов функции.

## Arguments in functions

- Функция получает собственные positional parameters.

- "$1", "$2", "$3"... внутри функции относятся к аргументам, переданным функции.

- "$#" внутри функции — количество аргументов функции.

Пример:

greet() {

    echo "Hello, $1 from $2"

}

greet Alex Kyiv

"$1" → Alex

"$2" → Kyiv

"$#" → 2

Важно:

"$1" скрипта и "$1" функции — разные контексты.

Например:

bash script.sh check test.txt

"$1" скрипта → check

"$2" скрипта → test.txt

check_file "$2"

Внутри функции:

"$1" → test.txt

То есть значение "$2" скрипта было передано функции как её первый аргумент.

Передача аргументов:

greet "$1" "$2"

## Аргументы скрипта передаются функции при её вызове.

return - Завершает выполнение текущей функции; передаёт exit status вызывающему коду; не завершает весь скрипт.

exit - Завершает весь скрипт.

Главная разница:

return → завершает функцию

exit → завершает скрипт

## Function exit status

Функция может вернуть exit status:

check_file() {

    if [ -f "$1" ]; then

        return 0

    else

        return 1

    fi

}

После вызова:

check_file "$1"

result="$?"

"$?" - содержит exit status функции.

## Функцию можно проверять напрямую через if:

if check_file "$1"; then

    echo "Check passed"

else

    echo "Check failed"

fi

В этом случае if получает exit status функции напрямую.

0 → then

не 0 → else

Функции могут выполнять действие и одновременно сообщать вызывающему коду, успешно ли оно выполнено.
