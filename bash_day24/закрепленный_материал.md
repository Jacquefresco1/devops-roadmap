# День 24 — закреплено практикой

## Процессы
- ps aux — все процессы; ps aux | grep X находит и сам grep (лишняя строка)
- top — живой мониторинг, выход q
- ps auxww — без обрезки строки по ширине окна
- зачем: найти, что грузит систему, жив ли сервис, узнать PID для kill

## kill и фоновые задачи
- kill PID = SIGTERM (-15, вежливо); kill -9 = SIGKILL (принудительно, только если -15 не помог)
- killall имя — по имени, а не по PID
- cmd & — в фон; jobs — фоновые задачи ЭТОЙ сессии; fg %1 — на передний план; Ctrl+Z — пауза; bg %1 — продолжить в фоне
- Ctrl+C — убить процесс на переднем плане

## systemctl
- status / start / stop / restart / enable / disable; list-units --type=service
- cron — сервис запуска команд по расписанию
- SUB: running — работает постоянно, exited — отработал один раз при старте
- выход из длинного status — q, или --no-pager

## Сеть
- IP-адрес (кто) + порт (какой сервис): 22 ssh, 53 DNS, 80 http, 443 https
- 127.0.0.1 — только эта машина; 0.0.0.0 — все интерфейсы (доступ зависит и от сети вокруг)
- ss -tuln — кто слушает; -p показывает процесс (чужие — только с sudo)
- TCP: LISTEN, UDP: UNCONN (у UDP нет соединений)
- в ss имя MainThread — это имя потока; настоящую программу ищем по PID: ps auxww | grep PID
- ping -c 3 host — доступность, -c ограничивает число пакетов

## curl
- curl -I url — только заголовки (статус: 200 ок, 404 не найдено)
- curl -s url | grep -oi "<title>.*</title>" — -o только совпавшая часть, -i без учёта регистра
- страница может быть одной длинной строкой: grep без -o выведет её целиком
- в интерактивном терминале grep — алиас на grep --color=auto; в скриптах алиасов нет
- цвет: GREP_COLORS='mt=01;32' grep --color=auto ... (имя переменной должно быть именно таким, программа ищет только его)
- VAR=значение команда — переменная только для этой команды

## SSH
- пара ключей: приватный (у тебя, 600) + публичный (на сервере, 644)
- вход: сервер даёт задачу, клиент подписывает приватным ключом, сервер проверяет подписью публичного; сам ключ по сети не идёт
- ssh откажется работать с приватным ключом, если права шире 600 (UNPROTECTED PRIVATE KEY FILE)
- passphrase — шифрует приватный файл на диске, серверу не передаётся
- ~/.ssh/authorized_keys на сервере — список ПУБЛИЧНЫХ ключей; опасна возможность писать в него, права 600
- known_hosts — запомненные серверы; fingerprint — короткий отпечаток ключа
- Connection refused = на порту никто не слушает (sshd не запущен)
- потерян приватный ключ: новая пара, новый публичный на сервер, старый убрать из authorized_keys (потерян и украден выглядят одинаково)
- доступ = обе половины сразу: публичный в списке на сервере И приватный у клиента
