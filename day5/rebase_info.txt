## Day 5
## Rebase

## 1. Что такое rebase

rebase переносит commit’ы текущей ветки поверх новой базы.

Было:
A ── B ── C       Linux
     \
      D ── E      feature

После git rebase Linux:
A ── B ── C ── D' ── E'

D' и E' — новые commit’ы, потому что их родитель изменился.

## 2. Как Git определяет, что переносить

Git находит общий предок двух веток и берёт commit’ы текущей ветки, которых нет в целевой ветке.

То есть rebase не определяет «мои commit’ы» по автору. Он смотрит на структуру графа commit’ов.

## 3. Merge vs Rebase

merge:
A ── B ── C ── M
     \        /
      D ─────E

Сохраняет обе линии истории и создаёт merge commit.

rebase:
A ── B ── C ── D' ── E'

Переписывает текущую ветку и делает историю линейной.

## 4. Rebase с конфликтом

При конфликте:

git rebase Linux
        ↓
CONFLICT
        ↓
исправить файл
        ↓
git add
        ↓
git rebase --continue

При merge после разрешения конфликта мы делали git commit.

При rebase вместо этого используем git rebase --continue.

## 5. --abort

Работает, пока rebase не завершён.
rebase идёт
↓
git rebase --abort
↓
возврат к состоянию до rebase

После успешного rebase --abort уже не работает.

Если нужно восстановить уже завершённое старое состояние — используем reflog и при необходимости reset.

## 6. --skip

git rebase --skip
Не «пропускает конфликт».

Он говорит Git:

не переносить текущий commit вообще и продолжить rebase со следующим.

Поэтому применять его вслепую опасно — можно выкинуть нужный commit.

## 7. Rebase и push

Если rebase переписал уже опубликованный commit, обычный push может дать:

non-fast-forward

Потому что:
GitHub:
A ── B ── L

local:
A ── B ── C ── L'

L и L' — разные commit’ы.

Тогда для осознанного переписывания remote:

git push --force-with-lease

Он разрешает перезапись, но предварительно проверяет, что remote не изменился неожиданно.

## 8. --force vs --force-with-lease

--force
→ «перезапиши remote моей историей»

--force-with-lease
→ «перезапиши, но только если remote всё ещё там,
   где я ожидаю»

--force-with-lease — предпочтительный вариант, когда действительно требуется force push.
