## Скрипты на изученном материале
- useradd/groupadd/usermod с sudo и проверкой exit-кода через локальные переменные status/status1
- проверка "уже существует" ДО действия: if id "$1" &>/dev/null — надёжнее, чем разбирать код ошибки после
- &>/dev/null перенаправляет И stdout, И stderr разом в "пустоту"; if смотрит на код возврата команды напрямую, без промежуточного $?
- sudo echo ... > file не работает — > выполняется твоим шеллом ДО sudo; нужно sudo bash -c 'echo ... > file'

## awk — что не проходили раньше
- || внутри условия, та же логика что && в bash if: $NF==403 || $NF==500 { print $1 }
- awk 'условие' без { } по умолчанию = { print $0 }, вся строка — этого достаточно для подсчёта через wc -l

## find + вложенность
- awk -F '/' '{ print $2 }' для имени файла ломается при вложенных путях — $NF берёт ПОСЛЕДНЕЕ поле, независимо от глубины пути

## Главный баг дня: $(...) обрезает завершающий перевод строки
- grep -oi "x" file | wc -l — верно, считает сразу в потоке
- count=$(grep -oi "x" file); echo "$count" | wc -l — ЗАНИЖАЕТ на 1 (без -n) или ЗАВЫШАЕТ на 1 при пустом выводе (с -n), потому что command substitution срезает последний \n
- вывод: если результат нужен только один раз — считать сразу в pipe, не прогонять через переменную и echo. Переменная нужна, когда результат используется несколько раз дальше (как count2 с номерами строк)

## systemd: service vs socket
- служба может быть "dead" (не запущена), но порт всё равно слушается — потому что есть ОТДЕЛЬНЫЙ юнит ...socket (например ssh.socket), который сам всегда активен и поднимает service по первому подключению
- ssh.socket = "звонок у двери", ssh.service = тот, кто реально отвечает на звонок
- Loaded: enabled/disabled — поднимется ли юнит сам при старте системы; Active: dead/running — работает ли он прямо сейчас; это две разные вещи
- не универсальное правило Linux, конкретная настройка конкретного дистрибутива/образа — встречается не везде
