# День 21 — закреплено практикой

## grep -E + regex — механика проверена
- {n,m} = повторение ОДНОГО элемента, не позиции (5[0-9]{2} = 500-599, но 5[0-9]{2,3} даёт и 4-значные)
- ^ и $ — разные концы, ставятся отдельно там, где нужны по смыслу
- \. — экранирование точки, иначе "любой символ"
- (a|b) без скобок "растаскивает" остальной паттерн — POST|GET$ ≠ (POST|GET)$

## sed — механика проверена
- s/old/new/ = только первое совпадение, /g = все
- -i меняет файл, без -i — только вывод, но замена ВЫПОЛНЯЕТСЯ в любом случае (не то же самое, что grep)
- d по номеру — ненадёжно (позиция "плавает"), d по паттерну — надёжно
- -n + p — вывод конкретных строк, без -n дублирование
- capture groups (...) + \1 — оставить только нужный кусок строки
- адресация /pattern/s/// — ограничить команду конкретными строками
- смена разделителя s#...#...# — когда в тексте много /

## pipe — механика проверена
- grep | grep | sed — можно сужать в несколько шагов подряд
- после | команда читает stdin, не файл — "$1" там не нужен
- -i не работает после | (нет исходного файла)

## Баги, которые реально ловил у себя (держать в голове перед запуском)
- незакрытая { в функции → синтаксическая ошибка в конце файла
- забытый 3-й / в s/// → unterminated command
- забытый файл-аргумент у grep/sed → "зависание" = на самом деле ждёт stdin (Ctrl+C)
- $ внутри capture group перед .* → логическое противоречие, паттерн никогда не совпадёт
