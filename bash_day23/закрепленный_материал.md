# День 23 — закреплено практикой

## Права доступа
- ls -l: 10 символов = тип | rwx владельца | rwx группы | rwx остальных
  (тип: - файл, d папка; бывают ещё l, b, c, p)
- r=4, w=2, x=1. chmod в числовом виде требует ровно 3 цифры:
  chmod 6 file = 006 (у владельца вообще нет прав) — моя ошибка
- 644 обычный файл, 755 папка/скрипт, 600 секретное, 750 (владелец всё, группа r-x, остальные ничего)
- x у файла нужен для ./script.sh; bash script.sh работает и без x (нужен только r)
- Папка: r = видеть список имён, x = заходить и открывать файлы по имени, w = создавать/удалять/переименовывать
  r без x: ls работает, cat файл внутри — Permission denied
- Удаление файла зависит от w у ПАПКИ, а не у файла
  (файл 000 в папке 755 удаляется; файл 777 в папке без w — нет)
- w у файла = менять его содержимое. Права папки и файла — две независимые системы
- 777 — это теоретический максимум, в реальности так почти не делают

## umask и chown
- umask 0022: файлы 666-022=644, папки 777-022=755; первая цифра — спецправа (setuid/setgid/sticky), обычно 0
- x новым файлам автоматически не ставится
- chown user:group file, chown :group file. Передать файл другому пользователю можно только с sudo

## sudo
- одна команда с правами root; спрашивает ТВОЙ пароль, не root
- пароль кэшируется (~15 минут): sudo -k сбрасывает кэш
- sudo -l — что тебе разрешено; sudo touch /root/x пройдёт, без sudo — Permission denied
- sudo ≠ быть другим пользователем: файлы, созданные через sudo, принадлежат root
- su testuser — стать пользователем (файлы будут его, доступ через его группы)
- проводник Windows не наследует su из терминала, /home/testuser через него закрыт

## Пользователи и группы
- /etc/passwd: имя:x:UID:GID:комментарий:домашняя_папка:оболочка. x = пароль лежит отдельно
- поле оболочки: /bin/bash — пускает в терминал; /usr/sbin/nologin — вход запрещён (служебные аккаунты: www-data, mysql)
- sh, bash, zsh — разные оболочки; #!/bin/bash в скрипте не зависит от логин-оболочки
- у каждого пользователя есть основная группа (создаётся сама, имя = имя пользователя); дополнительные — через usermod -aG
- usermod -G без -a ЗАМЕНЯЕТ все дополнительные группы
- группа — отдельная сущность, в неё вступают пользователи: доступ выдаётся и снимается одной командой, а не правкой всех файлов
- домашняя папка нового пользователя: drwxr-x--- (остальным закрыта)
- id — UID, GID и все группы одной строкой
